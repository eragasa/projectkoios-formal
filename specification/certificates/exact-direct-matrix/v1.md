# Exact direct-matrix certificate schema v1

## Status and authority

Identifier: `PKF-EXACT-DIRECT-MATRIX-PILOT/1`.

This is the canonical Formal-owned version-1 schema extracted from the reviewed synthetic pilot.
It specifies canonical bytes, exact rational-complex semantics, authentication, theorem bindings,
single-replay lifecycle, authoritative results, failure precedence, resource limits, and fixture
obligations. It is source-neutral and does not belong to KSD or any other computational owner.

Version 1 is retained for audit and compatibility only. Its grammar was extracted from the
independently reviewed pilot plan and normalized into normative wording. Independent review of this
extracted document identified a derived-rational resource ambiguity; the corrected document passed
focused rereview and is frozen as the audit-retained v1 schema. It binds one independent replay
and is not an implementation target under the mandatory Rust-and-Mojo architecture. Version 2
supersedes it for future implementation. Neither version authenticates producer origin, external source
fidelity, runtime execution, applicability, scientific adequacy, or publication status.

Lean is the mathematical authority for theorem application. A v1 replay is conformance evidence,
not theorem authority. This specification does not authorize implementation, execution, retention,
commit, push, evidence promotion, or publication.

## Canonical package shape

A pilot package is a directory containing exactly two regular files:

```text
body.pkfb
authentication.pkfa
```

Symlinks, devices, archives, additional files, path traversal, remote references, and external
payload references are outside the schema. File names are transport labels, not identity. The
checker authenticates the bytes and the package identity inside `body.pkfb`. Replay and checker
results are written outside the two-file input directory and cannot modify it.

The body uses `PKF-CANONICAL-BINARY/1`. The envelope uses
`PKF-DETACHED-AUTHENTICATION/1`. Both encodings are fixed-field binary records. They are not
self-describing extensible maps. A field addition, field removal, reordered field, changed primitive
encoding, new scalar class, or changed digest preimage requires a new major identifier.

### Primitive encodings

All byte strings below are concatenated without padding or alignment.

| Primitive | Canonical encoding |
|---|---|
| `octet` | one byte |
| `nat` | unsigned LEB128, shortest encoding only, maximum value `2^32 - 1` |
| `raw` | `nat` byte length followed by exactly that many bytes |
| `ascii` | `raw` whose bytes are all in `0x20`--`0x7e`; identities must be nonempty and have no leading or trailing ASCII space |
| `magnitude` | `raw` big-endian unsigned magnitude; zero is empty; nonzero values have no leading zero byte |
| `integer` | one sign octet (`0` nonnegative, `1` negative) followed by `magnitude`; zero must use sign `0` |
| `positive` | nonempty `magnitude` with value greater than zero |
| `rational` | `integer` numerator followed by `positive` denominator |
| `complex-rational` | `rational` real part followed by `rational` imaginary part |
| `sequence<T>` | `nat` element count followed by exactly that many canonical `T` values |
| `option<T>` | octet `0` for absent or octet `1` followed by one canonical `T`; every other tag rejects |

Every rational must be normalized: denominator positive, numerator and denominator coprime, and zero
encoded as numerator zero with denominator one. The parser rejects negative zero, denominator zero,
nonminimal LEB128, leading magnitude zeros, unreduced fractions, truncation, trailing bytes, and any
value exceeding a declared resource bound.

`ascii` preserves exact bytes; it does not perform Unicode normalization because non-ASCII text is
not admitted. Ordered carrier labels must be unique byte strings.

canonical alternate semantic value rather than collapsing it into a generic parse error.

Matrix dimensions are derived from the single carrier cardinality and are not repeated. The fixed
entry count prevents missing, duplicate, or excess entries. Matrix A and B share the same carrier,
space, basis, scalar unit, and energy-reference identity by construction. A producer cannot supply
norms, eigenvalues, aggregate errors, Hermiticity flags, or theorem conclusions.

The UUID syntax check does not prove global uniqueness. Phase 1 binds the declared package identity
to bytes and rejects duplicate identities within one batch. Cross-run replay and global uniqueness
remain ledger obligations outside this repository; the audit record must say so.

The checker rejects an envelope identity that differs byte for byte from the corresponding body
identity. Signatures are deliberately unsupported; a descriptive producer identity is not a
signature.

### Digest preimage

Let `body_bytes` be the complete bytes of `body.pkfb`, including its magic and end marker. The only
accepted digest is:

```text
SHA-256(
  UTF8("PKF-EXTERNAL-MATRIX-FRAME-BINDING/body/v1")
  || BYTE(0x00)
  || body_bytes
)
```

The detached envelope, digest bytes, and any future signatures are excluded from the preimage. The
contract, pilot schema, canonicalization identity, theorem revision, profile, semantic identities,
and all matrix entries are inside `body_bytes` and are therefore bound. The implementation must
compare all 32 digest bytes without accepting prefixes or case-encoded text.

SHA-256 establishes byte identity under its standard cryptographic assumption. It does not prove
producer correctness, origin, global package uniqueness, or scientific applicability.

## Exact semantic decoding

For cardinality `n`, decoding constructs the carrier `Fin n`. Label `labels[i]` is metadata bound to
index `i`; it does not create a new quotient or inferred ordering.

A normalized rational pair `(p, q)` first denotes a computational retained rational value with
arbitrary-size integer numerator and positive denominator. A retained complex value is the pair
`QComplex = (re, im)` of those rationals, with computational equality, negation, subtraction,
conjugation `(re, im) ↦ (re, -im)`, and norm square `re^2 + im^2`.

The row-major entry at offset `i*n + j` denotes a retained rational-complex matrix entry `(i, j)`.
No transpose, conjugation, column-major option, one-based index, or source-format convention exists
in Phase 1.

Hermiticity is executed on the retained representation, not by invoking equality on `ℂ`:

```text
A.re[i,j] = A.re[j,i]  and  A.im[i,j] = -A.im[j,i]
B.re[i,j] = B.re[j,i]  and  B.im[i,j] = -B.im[j,i]
```

Only after those checks succeed does the semantic map cast each retained entry to

```text
((re : ℚ) : ℂ) + ((im : ℚ) : ℂ) * Complex.I.
```

The implementation must prove that the cast commutes with conjugation and that successful retained
Hermiticity implies `A.IsHermitian` and `B.IsHermitian` for the cast matrices. It must not rely on
Mathlib's noncomputable classical complex equality as an executable decision procedure. The exact
Frobenius-power audit uses the retained rational formula
`sum i,j, ((A.re-B.re)^2 + (A.im-B.im)^2)` and a bridge theorem to the cast complex norm-square sum.
A producer-supplied assertion cannot satisfy any premise.

sum i, sum j, normSq((A-B)[i,j])

may be computed independently as audit data, because rational complex `normSq` is rational. That

## Checker pipeline

The transport wrapper first reads file metadata and admits a checker invocation only when each input
length is at most `2^32 - 1`. A larger file is outside the checker invocation domain: the wrapper
returns transport error `INPUT_LENGTH_OUT_OF_DOMAIN`, fails closed, emits no authoritative result
record, and cannot produce acceptance. This ceiling
makes every admitted actual length representable by the frozen `nat`; it is distinct from the much
smaller semantic resource limits below.

The checker must execute these gates in order:

1. reject body or envelope size beyond fixed semantic limits before semantic allocation or hashing;
2. parse the envelope primitives left to right, retaining canonical but unsupported field values;
3. parse the body primitives left to right, retaining canonical but unsupported field values;
4. validate the decoded envelope and body fields in the exact reason-table order below;
5. recompute and compare the domain-separated body digest at its prescribed table position;
6. validate roles, source class, Formal revision, profile, carrier, and semantic identities at their
   prescribed table positions;
7. decode normalized retained rational-complex entries;
8. construct both retained matrices in the shared exact carrier and basis;
9. check retained rational-component Hermiticity computationally;
10. cast the matrices to `ℂ` and derive exact Lean Hermiticity proofs through the cast bridge;
11. instantiate all five frozen theorem targets;
12. derive exact rational Frobenius-power audit data and its complex bridge;
13. emit one deterministic result; and
14. require a separate conformance replay before the package is described as independently reviewed.

No later gate may repair, normalize, reorder, reduce, transpose, conjugate, or infer missing input.
Canonical normalization is a producer responsibility; noncanonical but mathematically equivalent
bytes reject.

## Dispositions and rejection reasons

The Phase 1 result type exposes exactly:

- `ACCEPTED_EXACT_BINDING`;
- `UNRESOLVED`; and
- `REJECTED`.

A valid body and envelope first produce `UNRESOLVED` while the independent conformance replay is
missing. The reference verifier then emits the separate replay record defined below. A final checker
invocation rechecks the package, validates and compares that replay record, and may emit
`ACCEPTED_EXACT_BINDING`. A failed or mismatched replay rejects. Unsupported scalar classes,
external sources, intervals, or enclosure requests reject because they are outside the Phase 1
schema. The implementation must not define `ACCEPTED_ENCLOSURE_BINDING`.

The result retains exactly zero or one reason. The checker stops at the first failing atomic check;
it never accumulates later reasons. It checks body size before envelope size, parses the envelope
left to right before the body, returns the first byte-offset parse error, validates decoded fields in
the table order below, checks Hermiticity of A before B, and checks replay only after all exact
premises and theorem applications succeed. A rational canonicality error encountered while parsing
an entry is `RATIONAL_NONCANONICAL`; an early end inside the fixed entry inventory is
`ENTRY_INVENTORY_INVALID`; bytes after the expected end marker are `TRAILING_BYTES`; every other
structural primitive error is the applicable envelope/body noncanonical reason. This precedence is
part of the schema.

| Code | Reason | First failing check |

## Checked result record

Every authoritative result contains the top-level schema identity, disposition, zero-or-one reason,
actual input lengths, explicit digest option tags, checker and toolchain identities, pinned theorem
source/profile, semantic and replay option tags, axiom/admission audit, and nonclaims.

A present `semantic-result` contains:

- package identity and creation timestamp;
- repeated-identity comparison results;
- theorem profile and all five declaration bindings;
- carrier identity, cardinality, ordered labels, space, basis, unit, energy-reference, and matrix-role identities;
- the six independent acceptance-level flags;
- exact Hermiticity premise results;
- deterministic semantic digests of matrices A, B, and A minus B;
- derived exact rational entrywise Frobenius power; and
- pointwise, maximum, square-sum, squared-RMS, and RMS conclusion records in distinct fields.

A present `replay-binding` contains the independent replay tool identity, source revision, file
digest, and outcome. Accepted and unresolved results require the full semantic record. Early rejected
results intentionally retain only the unconditional top level because undecoded semantic fields do
not yet exist.

The result must not serialize eigenvalue approximations, runtime eigensolver ordering, producer
norms, source-file claims, applicability claims, or scientific decisions.

`theorem-binding-result` is, in order: declaration ID `ascii`; module `ascii`; fully qualified
declaration name `ascii`; conclusion-class octet (`0` pointwise, `1` maximum, `2` square-sum,
`3` squared RMS, `4` RMS); and instantiation octet (`0` fail, `1` pass). Its sequence must equal the
five-row theorem table byte for byte and in order. This gives maximum, square-sum, squared-RMS, and
RMS conclusions distinct fixed records.

`replay-binding` is, in order: replay-schema identity `ascii`; verifier identity `ascii`; verifier
commit `git-id`; verifier tree `git-id`; ordinary replay-file digest `sha256`; and outcome octet
(`0` pass, `1` fail). Absence is the single octet `0`; presence is tag `1` followed by those fields.

`axiom-audit-entry` is, in order: fully qualified checker/soundness declaration name `ascii`;
admission octet (`0` none, `1` present); and a bytewise-sorted, duplicate-free `sequence<ascii>` of
axiom names. The top-level audit sequence is bytewise sorted by declaration name, duplicate-free,
and must match a checker-embedded release manifest. Accepted output requires a nonempty audit,
admission octet zero in every entry, and every axiom name in the closed set `propext`,
`Classical.choice`, or `Quot.sound`. This record reports the checked release manifest; it does not
cause Lean to inspect its own environment at runtime.

The eight set nonclaim bits mean, from least-significant to most-significant bit: producer origin not
authenticated, global UUID uniqueness not proved, external source fidelity not checked, runtime
arrays absent, eigensolver output absent, applicability not assessed, scientific adequacy not
assessed, and publication not authorized.

For reason code 0 all three digest options are absent, preventing resource rejection from forcing a
full read or hash of an oversized input. For every other disposition all three digest options are
present. Accepted output requires: no reason, present semantic and replay records, every comparison/
premise/theorem/replay octet equal to pass, all fixed identities equal, and a conforming axiom audit.
Unresolved output requires sole reason `INDEPENDENT_REPLAY_MISSING`, a fully passing semantic record,
and absent replay binding. The semantic option is present if and only if exact premises and all five
theorem applications completed; therefore its acceptance-level sequence is always
`1,1,0,1,0,0`, independently of the top-level replay disposition. Rejected output has exactly the
first-failure reason: its semantic option is absent for codes 0--26 and present for code 28; its
replay option is present for code 28 only when the complete replay record parsed before a comparison
or fail outcome. These variant rules eliminate implicit or implementation-selected missing values.

For any matrix `M`, its semantic digest is
`SHA-256(UTF8("PKF-EXACT-DIRECT-MATRIX/matrix/v1") || BYTE(0x00) || nat(n) || entries(M))`,
where `entries(M)` is the row-major sequence of normalized canonical `complex-rational` encodings
without a sequence count. The difference digest uses checker-derived normalized entries of `A-B`,
not producer bytes. A human-readable report is derived from the authoritative result and has no
independent authority.

## Independent conformance replay

The pilot requires a read-only reference verifier that is structurally independent of the Lean
producer path. A small repository audit script may:

- decode the fixed binary grammar independently;
- recompute SHA-256 with a standard-library implementation;
- reconstruct rational complex matrices;
- recheck exact Hermiticity;
- recompute exact rational Frobenius power; and
- compare its bounded record with the Lean checker output.

The reference verifier must not itself grant formal acceptance and must not be imported by the Lean
checker. Conversely, the Lean checker must not call the reference verifier. Agreement increases
implementation confidence but does not replace Lean soundness theorems or authenticate producer
origin.

The replay record uses `PKF-INDEPENDENT-CONFORMANCE-REPLAY/1` with the same canonical primitives and
this numbered fixed layout:

| Order | Replay field | Exact encoding |
|---:|---|---|
| 1 | magic | eight literal octets `PKFREPL1`, without a length prefix |
| 2 | replay-schema identity | `ascii`, exactly `PKF-INDEPENDENT-CONFORMANCE-REPLAY/1` |
| 3 | verifier tool identity | `ascii`, byte-for-byte equal to body field 13 |
| 4 | verifier commit | exactly 20 literal bytes without a length prefix |
| 5 | verifier tree | exactly 20 literal bytes without a length prefix |
| 6 | package identity | canonical UUID `ascii`, byte-for-byte equal to the body value |
| 7 | domain-separated body digest | exactly 32 literal bytes without a length prefix |
| 8 | carrier identity | `ascii`, byte-for-byte equal to the body value |
| 9 | carrier cardinality | `nat`, equal to the body value |
| 10 | ordered carrier labels | `sequence<ascii>`, byte-for-byte equal to body labels |
| 11 | space identity | `ascii`, equal to the body value |
| 12 | basis identity | `ascii`, equal to the body value |
| 13 | scalar-unit identity | `ascii`, equal to the body value |
| 14 | energy-reference identity | `ascii`, equal to the body value |
| 15 | matrix A semantic digest | exactly 32 literal bytes under the frozen matrix preimage rule |
| 16 | matrix B semantic digest | exactly 32 literal bytes under the frozen matrix preimage rule |
| 17 | difference semantic digest | exactly 32 literal bytes for independently derived normalized `A-B` |
| 18 | matrix A Hermiticity | octet `0` fail or `1` pass |
| 19 | matrix B Hermiticity | octet `0` fail or `1` pass |
| 20 | entrywise Frobenius power | normalized `rational`, independently derived |
| 21 | replay outcome | octet `0` pass or `1` fail |
| 22 | end marker | eight literal ASCII octets `ENDREPL1`, without a length prefix, followed by end of file |

The final Lean checker reparses this record and compares every repeated semantic value in table
order. Missing replay yields `UNRESOLVED`; a failed replay, mismatch, noncanonical replay, missing
revision field, or extra replay field yields `REJECTED`. A pass outcome requires both Hermiticity
octets to pass and all repeated or derived values to match.

The replay record is generated after the first unresolved check and is not inserted into
`body.pkfb`; doing so would create a lifecycle cycle. The final result binds the replay bytes by
ordinary SHA-256 and repeats the replay tool revision. The checker binds that declared revision but
cannot prove repository cleanliness, tool origin, or that the named tool produced the bytes; the
conformance procedure must verify those facts independently before describing the replay as
independent. A later retained audit bundle manifest is not part of Phase 1 and requires separate
review.

## Resource bounds

Freeze these pilot limits:

- transport invocation ceiling: each input file at most `2^32 - 1` bytes; a larger file is an
  out-of-domain fail-closed transport error with no authoritative result;
- body: at most 1 MiB;
- envelope: at most 4 KiB;
- replay record: at most 2 MiB; an oversized replay is `INDEPENDENT_REPLAY_FAILED` without forced
  hashing or parsing;
- matrix cardinality: 1--16;
- identity string: at most 128 bytes unless a smaller field limit is stated;
- source description: at most 256 bytes;
- carrier label: at most 64 bytes;
- body-input rational numerator or denominator magnitude: at most 256 bytes; and
- one package per checker invocation unless a later batch wrapper supplies a duplicate-ID set.

The 256-byte magnitude limit applies only to rational components decoded from the body matrices. It
does not apply to the checker-derived Frobenius-power rational serialized in the result or to the
independently derived copy serialized in the replay. Those two fields use arbitrary-size normalized
canonical rationals. A checker or replay route must not return `RESOURCE_BOUND_EXCEEDED` merely
because either derived magnitude exceeds 256 bytes.

The frozen input and dimension bounds nevertheless give a finite analytical ceiling. A 256-byte
input magnitude is less than `2^2048`; the unreduced row-major Frobenius-power construction over at
most 256 entries gives numerator and denominator magnitudes of fewer than 524,291 bytes each.
Normalization can only reduce them. One encoded derived rational occupies fewer than 1,048,590
bytes including its sign and canonical length prefixes; every other bounded replay field contributes
less than 64 KiB, so the complete replay fits the 2 MiB replay ceiling. This analytical consequence
is not an additional rational-magnitude rejection threshold and does not freeze an intermediate
semantic-operation schedule. An implementation whose integer backend
cannot retain the exact normalized value is nonconforming; it may not replace that value with an
authoritative resource rejection.

Version 1 remains ineligible for new implementation under the mandatory two-native-route
architecture. Limits are implementation safety bounds, not mathematical theorem hypotheses.
Changing an encoding or meaning requires a new major schema.

## Fixture inventory

Formal may retain these synthetic conformance fixtures because they contain no external owner data.
Each accepted fixture needs hand-auditable source expressions, canonical bytes, expected digests,
and expected checker/replay records.

### Acceptance fixtures

1. `dimension-one-equal`: equal `1 x 1` rational Hermitian matrices;
2. `dimension-two-real`: distinct real symmetric `2 x 2` matrices;
3. `dimension-two-complex`: noncommuting complex Hermitian matrices with nonzero imaginary
   off-diagonal entries;
4. `dimension-three-repeated-spectrum`: a Hermitian pair with repeated eigenvalues, without
   eigenvector labels; and
5. `dimension-sixteen-boundary`: sparse matrices at the dimension limit.

### Adversarial fixtures

At minimum cover:

- the transport-length boundary, including `2^32 - 1` and an abstracted larger length that returns
  `INPUT_LENGTH_OUT_OF_DOMAIN` without a result;
- every truncated primitive and field boundary;
- nonminimal LEB128;
- magnitude leading zero, negative zero, zero denominator, negative denominator encoding, and
  unreduced rational;
- invalid ASCII, overlong strings, malformed UUID, duplicate carrier labels, zero dimension, and
  dimension 17;
- missing or excess entries, plus row/column-reordered, transposed, or conjugated entries paired
  with a stale digest;
- changed body with stale digest;
- changed envelope identity with unchanged body;
- digest prefix, wrong digest algorithm, nonzero signature count, and trailing bytes;
- wrong Formal commit, tree, profile, matrix A/B role, basis, unit, or energy-reference identity;
- non-Hermitian A, non-Hermitian B, and tolerance-small but exactly nonzero asymmetry;
- producer-supplied norm or eigenvalue bytes, which appear only as trailing unsupported bytes and
  reject;
- ascending diagnostic eigenvalues supplied as extra bytes, which reject;
- same package identity presented twice to a batch wrapper, which rejects at the wrapper boundary;
  and
- valid exact bytes without the required independent replay record, which remain `UNRESOLVED` at
  the lifecycle boundary; and
- multi-failure inputs for each precedence boundary, including equal unsupported body/envelope
  contract identities plus a nonzero signature count and wrong matrix role plus non-Hermitian
  entries, asserting that only the first prescribed reason appears and that result bytes reproduce
  exactly.

A rehashed, semantically changed self-contained synthetic package, including a transposed or
conjugated Hermitian matrix, is not cryptographically invalid merely because it differs from an
earlier fixture. With a new package identity it is a different synthetic package. With a reused
identity it is detectable only against an external batch or replay ledger. Phase 1 must not claim
that a bare digest authenticates producer intent or expected scientific entries.
